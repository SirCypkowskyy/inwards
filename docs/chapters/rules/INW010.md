# INW010 `unknown-first-party`

## What it does

Reports a static import, in a file in a layer, of a first-party module that doesn't exist, and a relative import that climbs above the top-level package, which Python always refuses. An import is first-party when a prefix of it is a module of the project.

Only the module part is checked: `X` of `from X import name`, and the whole name of `import X` or `from X import *`. Existence is probed on disk the way Python imports, so namespace packages, stubs (`.pyi`) and compiled extensions (`.so`, `.pyd`, `.pyx`, `.pyc`) count. The fix lists the three modules of the same package closest to the missing name. Packages whose `__init__.py` extends `__path__` (`pkgutil.extend_path`, `declare_namespace`) are skipped.

An import INW010 reports gets no [INW006](INW006.md) as well, and an outward import [INW001](INW001.md) reports gets no INW010: INW001's fix deletes the import, while INW010's would create the module.

## Why is this bad

Agents invent plausible modules: `from shop.domain.pricing import DiscountPolicy`, where `pricing` doesn't exist. Without a check it surfaces as an `ImportError` at test time, if a test covers the file. INW010 flags it in the same hook run, before any test is written, and points at the near miss the agent probably meant.

## Example

With the layers from [INW001](INW001.md#example), and `prices.py` and `money.py` in the domain:

<!-- e2e -->

```sh
touch shop/domain/prices.py shop/domain/money.py
```

<!-- e2e -->

```python title="shop/domain/order.py"
from shop.domain.pricing import DiscountPolicy
```

<!-- e2e -->

```sh
inwards check
```

<!-- e2e -->

```text
shop/domain/order.py:1:33: INW010 "shop.domain.pricing" is not a module of this project: "shop.domain" has no "pricing".
  fix: Import a module that exists, or create "shop.domain.pricing" first.
    1. Check the name. The closest modules in "shop.domain": `shop.domain.prices`, `shop.domain.money`.
    2. If the code isn't written yet, create "shop.domain.pricing" before importing it.
    3. Don't wrap the import in try/except ImportError; Inwards checks those too.
  docs: https://sircypkowskyy.github.io/inwards/rules/INW010/
```

Fixed: the policy lives in `prices.py`.

<!-- e2e -->

```python title="shop/domain/prices.py"
class DiscountPolicy:
    pass
```

<!-- e2e -->

```python title="shop/domain/order.py"
from shop.domain.prices import DiscountPolicy
```

<!-- e2e -->

```sh
inwards check
```

## How to fix

1. Check the name against the closest modules the fix lists, and import the one that exists.
2. If the code isn't written yet, create the module first, then import it.
3. Don't wrap the import in `try/except ImportError`: the rule checks it there too, and the code would still fail at runtime.

## Fix safety

No automatic fix (`autofix: false`). The closest name by edit distance isn't always the module the code meant, so a person or the agent has to pick.

## Configuration

Severity error. `[tool.inwards.rules]` can turn the rule off or make it a warning ([Configure rules](index.md#configure-rules)). One import can be suppressed on its line, for example a module generated at build time:

```python
from shop.domain._version import VERSION  # inwards: ignore[INW010] reason="generated by the build"
```

## Known limitations

- `from shop.domain import pricing` passes when `shop/domain` is a package, since `pricing` could be a name its `__init__.py` defines ([ADR-025](../05-ADR.md#adr-025-inw010-probes-the-disk-for-existence-and-checks-only-the-module-part-of-an-import)).
- A module generated at build time (`_version.py`, `*_pb2.py`) is reported until it exists in the checkout ([#160](https://github.com/SirCypkowskyy/inwards/issues/160)), and so is an optional import behind `try/except ImportError`.
- A namespace package shared with an installed distribution is reported as missing ([#161](https://github.com/SirCypkowskyy/inwards/issues/161)).
- Dynamic imports aren't checked for existence.
- The language server doesn't notice an `__init__.py` that starts extending its `__path__` until a file is created or deleted.
