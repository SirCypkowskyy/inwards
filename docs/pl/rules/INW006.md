# INW006 `unassigned-module`

## Co robi { #what-it-does }

Inwards sprawdza tylko kod, który należy do warstwy. INW006 pokazuje resztę:

| Diagnostyka | Gdzie | Poziom |
|---|---|---|
| Plik w warstwie importuje własny kod, który nie należy do żadnej warstwy, statycznie albo dynamicznie. Dotyczy to też pakietu nad warstwami: `from shop import x` uruchamia `shop/__init__.py`, którego nie ma żadna warstwa | import | błąd |
| Pakiet poza wszystkimi warstwami i poza `ignore` | jego `__init__.py` albo pierwszy plik | ostrzeżenie |
| Prefiks warstwy, do którego nie pasuje żaden moduł | `pyproject.toml` | ostrzeżenie |
| Warstwa, do której żadnego prefiksu nie pasuje żaden moduł | `pyproject.toml` | błąd |
| W trakcie sesji agenta: prefiks, który na starcie sesji pasował do modułów, a teraz nie pasuje do żadnego, albo kod warstwy przeniesiony poza wszystkie warstwy | Stop gate | błąd |

Wpisy `ignore` w `[tool.inwards]` pasują do całych segmentów nazwy w dowolnym miejscu, więc `ignore = ["migrations"]` obejmuje `shop.orders.migrations`. Nieznane klucze i prefiks wymieniony w dwóch warstwach to błędy konfiguracji (kod wyjścia 2).

## Dlaczego to źle { #why-is-this-bad }

Gdy import do warstwy zewnętrznej jest zablokowany, agent może utworzyć nowy pakiet, którego nie ma żadna warstwa, `shop/persistence/` albo `shop/common/`, i zaimportować go zamiast tamtej. Nic nie sprawdza, co importuje nowy pakiet, więc może swobodnie sięgać do bazy danych. Przeniesienie warstwy (`git mv shop/domain shop/core`) opróżnia jej prefiks i wyłącza całą warstwę. INW006 zamyka obie drogi, a martwy prefiks w ręcznie pisanej konfiguracji (literówka, pakiet o zmienionej nazwie) dostaje tę samą uwagę.

## Przykład { #example }

Z warstwami z [INW001](INW001.md#example) agent umieszcza typ wartości w nowym pakiecie `shop.common` i importuje go z domeny:

<!-- e2e -->

```sh
mkdir -p shop/common
touch shop/__init__.py shop/common/__init__.py
```

<!-- e2e -->

```python title="shop/common/money.py"
from dataclasses import dataclass


@dataclass(frozen=True)
class Money:
    cents: int
```

<!-- e2e -->

```python title="shop/domain/order.py"
from shop.common.money import Money


def total(prices: list[Money]) -> Money:
    return Money(sum(p.cents for p in prices))
```

<!-- e2e -->

```sh
inwards check
```

<!-- e2e -->

```text

  fix: Put the code under a layer's package, or ask the user to assign "shop.common".
    1. If this code is part of the application, move it under the package of the layer it belongs to.
    2. Otherwise ask the user to add "shop.common" to a layer, or to `ignore` in [tool.inwards] if it is tooling. Don't edit [tool.inwards] yourself.
  docs: https://sircypkowskyy.github.io/inwards/rules/INW006/

shop/domain/order.py:1:31: INW006 Layer "domain" imports "shop.common.money.Money", which belongs to no layer, so nothing checks what "shop.common" imports.
  fix: Move the code into a layer, or ask the user which layer "shop.common" belongs to.
    1. If the code belongs to "domain" or an inner layer, move it under that layer's package and import it from there.
    2. Otherwise ask the user to add "shop.common" to a layer in [tool.inwards]. Don't edit [tool.inwards] yourself.
  docs: https://sircypkowskyy.github.io/inwards/rules/INW006/
```

Po poprawce: `Money` to wartość domenowa, więc trafia do domeny.

<!-- e2e -->

```sh
mv shop/common/money.py shop/domain/money.py
rm -r shop/common
```

<!-- e2e -->

```python title="shop/domain/order.py"
from shop.domain.money import Money


def total(prices: list[Money]) -> Money:
    return Money(sum(p.cents for p in prices))
```

<!-- e2e -->

```sh
inwards check
```

Prefiks, do którego nie pasuje żaden moduł, daje ostrzeżenie w `pyproject.toml`:

<!-- e2e -->

```toml title="pyproject.toml"
[tool.inwards]
layers = [
  { name = "domain",         modules = ["shop.domain"] },
  { name = "application",    modules = ["shop.application"] },
  { name = "infrastructure", modules = ["shop.infrastructure", "shop.adapters"] },
]
```

<!-- e2e -->

```sh
inwards check
```

<!-- e2e -->

```text
pyproject.toml:5:64: INW006 (warning) "shop.adapters" (layer "infrastructure") matches no module.
  fix: Ask the user to fix or remove "shop.adapters" in [tool.inwards].
    1. Check the prefix for a typo: a prefix that matches nothing leaves the code it was meant for unchecked.
    2. Don't edit [tool.inwards] yourself; tell the user.
  docs: https://sircypkowskyy.github.io/inwards/rules/INW006/
```

## Jak naprawić { #how-to-fix }

- **Import kodu bez warstwy:** jeśli kod należy do warstwy importującej albo bardziej wewnętrznej, przenieś go do pakietu tej warstwy i importuj stamtąd. W przeciwnym razie użytkownik decyduje, do której warstwy należy, i dopisuje jego prefiks w `[tool.inwards]`.
- **Pakiet poza wszystkimi warstwami:** przenieś go do warstwy albo poproś użytkownika, żeby przypisał go do warstwy lub dopisał do `ignore`, jeśli to narzędzia (testy, skrypty, migracje).
- **Martwy prefiks:** popraw literówkę albo usuń prefiks. Agent mówi o tym użytkownikowi; nie edytuje konfiguracji.
- **Warstwa przeniesiona w trakcie sesji:** przenieś ją z powrotem.

## Bezpieczeństwo poprawki { #fix-safety }

Brak automatycznej poprawki (`autofix: false`). To, gdzie należy kod, jest decyzją projektową, a każda zmiana konfiguracji należy do użytkownika.

## Konfiguracja { #configuration }

Poziom: błąd, z ostrzeżeniami z tabeli powyżej. `[tool.inwards.rules]` może wyłączyć regułę albo ustawić poziom każdej jej diagnostyki: przy `severity = { INW006 = "error" }` ostrzeżenie o pakiecie też staje się błędem ([Konfiguracja reguł](index.md#configure-rules)). Sprawdzenie układu w Stop gate (prefiks opróżniony albo kod warstwy przeniesiony od startu sesji) pomija tę tabelę, więc nawet `ignore = ["INW006"]` nie pozwala agentowi przenieść warstwy ([ADR-027](../05-ADR.md#adr-027-per-rule-select-ignore-and-severity-in-a-toolinwardsrules-table)). Diagnostykę importu można wyciszyć w jej linii przez `# inwards: ignore[INW006] reason="..."`.

W hookach Claude Code edycja z samymi ostrzeżeniami INW006 zostaje, a ostrzeżenia trafiają do agenta jako kontekst.

## Znane ograniczenia { #known-limitations }

- Importy wewnątrz nieprzypisanego pakietu nie są sprawdzane, dopóki użytkownik go nie przypisze; INW006 tylko go pokazuje.
- Serwer języka i `inwards check` ze ścieżkami jako argumentami sprawdzają pliki pojedynczo i nie zgłaszają martwych prefiksów. Robi to tylko sprawdzenie całego projektu.
- Moduły bez źródeł, głębokość `ignore`, przeniesienia pakietów najwyższego poziomu pod nową nazwą i sprawdzanie prefiksów w zakresie ścieżki są otwarte w [#86](https://github.com/SirCypkowskyy/inwards/issues/86).
- Import, który [INW010](INW010.md) zgłasza jako brakujący moduł, nie dostaje dodatkowo INW006.
