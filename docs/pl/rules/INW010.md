# INW010 `unknown-first-party`

## Co robi { #what-it-does }

Zgłasza statyczny import, w pliku w warstwie, własnego modułu, który nie istnieje, oraz import względny, który wychodzi ponad pakiet najwyższego poziomu, czego Python zawsze odmawia. Import jest własny, gdy jego prefiks jest modułem projektu.

Sprawdzana jest tylko część będąca modułem: `X` w `from X import name` i cała nazwa w `import X` albo `from X import *`. Istnienie jest sondowane na dysku tak, jak importuje Python, więc liczą się pakiety przestrzeni nazw, zaślepki (`.pyi`) i skompilowane moduły rozszerzeń (`.so`, `.pyd`, `.pyx`, `.pyc`). Poprawka wymienia trzy moduły z tego samego pakietu najbliższe brakującej nazwie. Pakiety, których `__init__.py` rozszerza `__path__` (`pkgutil.extend_path`, `declare_namespace`), są pomijane. Pod niejawnym pakietem przestrzeni nazw (bez `__init__.py` od pakietu najwyższego poziomu w dół) moduł, który ma inny członek workspace'u uv, liczy się jako istniejący, bo Python scala pakiet z obu członków ([Monorepo i workspace'y uv](../guides/configuration.md#monorepos)). Moduł objęty wzorcem z [`generated`](#generated-modules) liczy się jako istniejący, bo zapisuje go krok budowania.

Import zgłoszony przez INW010 nie dostaje dodatkowo [INW006](INW006.md), a import na zewnątrz zgłoszony przez [INW001](INW001.md) nie dostaje INW010: poprawka INW001 usuwa import, a poprawka INW010 tworzyłaby moduł.

## Dlaczego to źle { #why-is-this-bad }

Agenci wymyślają wiarygodnie brzmiące moduły: `from shop.domain.pricing import DiscountPolicy`, choć `pricing` nie istnieje. Bez sprawdzenia wychodzi to jako `ImportError` dopiero przy testach, o ile jakiś test obejmuje plik. INW010 zgłasza to w tym samym uruchomieniu hooka, zanim powstanie jakikolwiek test, i wskazuje bliską nazwę, o którą agentowi zapewne chodziło.

## Przykład { #example }

Z warstwami z [INW001](INW001.md#example) oraz `prices.py` i `money.py` w domenie:

<!-- e2e -->

```sh
touch shop/domain/prices.py shop/domain/money.py
```

<!-- e2e -->

```python title="shop/domain/order.py"
from shop.domain.pricing import DiscountPolicy
```

<!-- e2e -->

```sh
inwards check
```

<!-- e2e -->

```text
shop/domain/order.py:1:33: INW010 "shop.domain.pricing" is not a module of this project: "shop.domain" has no "pricing".
  fix: Import a module that exists, or create "shop.domain.pricing" first.
    1. Check the name. The closest modules in "shop.domain": `shop.domain.prices`, `shop.domain.money`.
    2. If the code isn't written yet, create "shop.domain.pricing" before importing it.
    3. Don't wrap the import in try/except ImportError; Inwards checks those too.
  docs: https://sircypkowskyy.github.io/inwards/rules/INW010/
```

Po poprawce: polityka rabatów mieszka w `prices.py`.

<!-- e2e -->

```python title="shop/domain/prices.py"
class DiscountPolicy:
    pass
```

<!-- e2e -->

```python title="shop/domain/order.py"
from shop.domain.prices import DiscountPolicy
```

<!-- e2e -->

```sh
inwards check
```

## Jak naprawić { #how-to-fix }

1. Porównaj nazwę z najbliższymi modułami z poprawki i zaimportuj ten, który istnieje.
2. Jeśli kodu jeszcze nie ma, najpierw utwórz moduł, a dopiero potem go importuj.
3. Nie owijaj importu w `try/except ImportError`: reguła sprawdza go i tam, a kod i tak zawiódłby w czasie działania.

## Bezpieczeństwo poprawki { #fix-safety }

Brak automatycznej poprawki (`autofix: false`). Nazwa najbliższa według odległości edycyjnej nie zawsze jest modułem, o który chodziło w kodzie, więc wybrać musi człowiek albo agent.

## Konfiguracja { #configuration }

Poziom: błąd. `[tool.inwards.rules]` może wyłączyć regułę albo zmienić ją w ostrzeżenie ([Konfiguracja reguł](index.md#configure-rules)).

### Moduły generowane { #generated-modules }

Niektóre moduły istnieją dopiero po kroku budowania: `orders_pb2.py` i `orders_pb2_grpc.py` z protoc, `_version.py` z setuptools-scm albo hatch-vcs. Checkout programisty je ma, a świeży checkout w CI nie. INW010 traktuje moduł objęty przez `generated` w `[tool.inwards]` jako istniejący, niezależnie od tego, czy plik jest ([ADR-029](../05-ADR.md#adr-029-generated-modules-pass-inw010-protoc-and-version-modules-by-default)):

<!-- config: fragment -->

```toml title="pyproject.toml"
[tool.inwards]
generated = ["*_pb2", "*_pb2_grpc", "_version", "shop.api.gen"]
```

- Wzorzec to nazwa modułu z kropkami, a każdy segment może używać `*` i `?`. Pasuje do całych segmentów w dowolnym miejscu rozwiązanej nazwy modułu, tak jak `ignore`: `*_pb2` obejmuje `shop.api.orders_pb2`, `_version` obejmuje `shop._version`, `shop.api.gen` wszystko w `shop/api/gen/`. Symbol wieloznaczny nigdy nie przechodzi przez kropkę.
- Nie ma zbiorów w nawiasach. Pusty segment, znak, którego nie może być w nazwie modułu (w tym `[` i `]`), albo wzorzec złożony z samych symboli wieloznacznych i kropek (`*`, `*.*`) to błąd konfiguracji (kod wyjścia 2). Żeby wyłączyć INW010, użyj `ignore = ["INW010"]` w `[tool.inwards.rules]`.
- Bez tego klucza lista to `["*_pb2", "*_pb2_grpc", "_version"]`. Ustawienie klucza zastępuje listę domyślną, więc jeśli nadal chcesz jej wzorców, wypisz je, a `generated = []` ją wyłącza.
- Klucz czyta tylko INW010. Pozostałe reguły nadal widzą moduł generowany, którego nie ma na dysku, jako brakujący: import takiego modułu skierowany na zewnątrz to nadal INW001, a INW006 wskazuje najbliższy istniejący pakiet.

Przy liście domyślnej import modułu z protoc, który nie został jeszcze wygenerowany, przechodzi:

<!-- e2e -->

```python title="shop/domain/order.py"
from shop.domain.orders_pb2 import Order
```

<!-- e2e -->

```sh
inwards check
```

Każdy inny import można wyciszyć w jego linii, z powodem:

```python
from shop.domain.legacy_rates import RATES  # inwards: ignore[INW010] reason="copied in by the deploy script, see #230"
```

## Znane ograniczenia { #known-limitations }

- `from shop.domain import pricing` przechodzi, gdy `shop/domain` jest pakietem, bo `pricing` może być nazwą zdefiniowaną w jego `__init__.py` ([ADR-025](../05-ADR.md#adr-025-inw010-probes-the-disk-for-existence-and-checks-only-the-module-part-of-an-import)).
- Zmyślony import, którego nazwę obejmuje wzorzec z `generated`, przechodzi INW010, domyślnie każdy moduł `*_pb2`, `*_pb2_grpc` albo `_version` (`shop.api.payments_pb2` bez `payments.proto`). Zawiedzie dopiero przy uruchomieniu kodu. Żeby wyłapywać takie importy, ustaw `generated = []` i uruchamiaj generator przed sprawdzeniem ([ADR-029](../05-ADR.md#adr-029-generated-modules-pass-inw010-protoc-and-version-modules-by-default)).
- Opcjonalny import za `try/except ImportError` jest zgłaszany.
- Pakiet przestrzeni nazw współdzielony z zainstalowaną dystrybucją jest zgłaszany jako brakujący ([#161](https://github.com/SirCypkowskyy/inwards/issues/161)). Przeszukiwani są tylko pozostali członkowie workspace'u uv, a serwer języka do nich nie zagląda.
- Importy dynamiczne nie są sprawdzane pod kątem istnienia.
- Serwer języka nie zauważa `__init__.py`, który zaczyna rozszerzać swój `__path__`, dopóki jakiś plik nie zostanie utworzony albo usunięty.
