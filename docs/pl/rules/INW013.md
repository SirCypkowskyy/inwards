# INW013 `async-blocking`

## Co robi { #what-it-does }

Opt-in, a po włączeniu błąd. Zgłasza synchroniczne wywołanie bazy danych, cache'u albo chmury wewnątrz `async def`, na samym wywołaniu. Liczą się dwa rodzaje wywołań:

- **Metoda blokującego odbiorcy.** Odbiorca to nazwa, której metody wykonują synchroniczne I/O:
    - parametr, którego adnotacja wskazuje blokujący typ: wprost, `Annotated[T, ...]`, `Optional[T]`, `T | None` albo alias zdefiniowany w tym samym pliku (`DbSession = Annotated[Session, Depends(get_db)]`);
    - nazwa, którą moduł albo funkcja przypisuje z wywołania blokującego typu lub fabryki (`cache = redis.Redis()`, `s3 = boto3.client("s3")`, `with Session(engine) as session`) albo opisuje nim w adnotacji (`client: Redis = make_client()`);
    - wywołanie takiego typu wprost w wyrażeniu: `Session(engine).scalar(query)`.
- **Wywołanie, które samo blokuje:** `connect` sterownika DB-API.

Wbudowana lista:

| Rodzina | Odbiorcy | Które metody się liczą |
|---|---|---|
| `Session` z SQLAlchemy i SQLModel | `sqlalchemy.orm.Session`, `scoped_session`, `sqlmodel.Session` | Te, które `AsyncSession` czyni awaitable, bo mogą wysłać SQL: `execute`, `scalar`, `scalars`, `get`, `get_one`, `flush`, `commit`, `rollback`, `delete`, `merge`, `refresh`, `connection`, `close`, `invalidate`, `reset`; do tego tylko synchroniczne `query` i `bulk_*` oraz `exec` z SQLModel. `add`, `add_all`, `expunge` i inne metody księgowe się nie liczą. |
| `Engine` i `Connection` z SQLAlchemy | `create_engine(...)` (z SQLAlchemy i SQLModel), `Engine`, `Connection` | Każda metoda poza `execution_options` i `get_execution_options`. |
| redis-py | `redis.Redis`, `StrictRedis`, `RedisCluster`, `redis.from_url` | Każda komenda. `pipeline`, `pubsub` i `lock` się nie liczą: budują obiekt i jeszcze niczego nie wysyłają. |
| boto3 | `boto3.client(...)`, `boto3.resource(...)` | Każda metoda poza tymi, które podpisują albo budują coś lokalnie: `generate_presigned_url`, `generate_presigned_post`, `get_paginator`, `get_waiter`, `can_paginate` i podzasób pisany wielką literą, taki jak `s3.Bucket("b")`. |
| Sterowniki DB-API | `sqlite3.connect`, `psycopg2.connect`, `psycopg.connect`, `pymysql.connect`, `MySQLdb.connect`, `mysql.connector.connect` i ich klasy połączeń | Samo wywołanie `connect` i każda metoda zwróconego połączenia. |

`extend-blocking-calls` i `extend-blocking-types` dodają własne pozycje. Pliki są sprawdzane niezależnie od warstwy; `modules` zawęża regułę do części z nich, na przykład do routerów.

## Dlaczego to źle { #why-is-this-bad }

`async def` działa na pętli zdarzeń. Kiedy synchroniczne wywołanie czeka na bazę danych, Redisa albo AWS, czeka też pętla, a z nią każde inne żądanie obsługiwane przez ten worker. FastAPI radzi używać `async def`, chyba że funkcja operacji ścieżki korzysta z kodu, który wykonuje blokujące I/O, a zwykłą funkcję `def` (trasę albo zależność) uruchamia w puli wątków, żeby nie blokowała serwera ([FastAPI: Concurrency and async / await](https://fastapi.tiangolo.com/async/)). Agenci kopiują `db: Session = Depends(get_db)` z tutorialu o SQL i dopisują `async def` do trasy. Testy przechodzą, bo wysyłają jedno żądanie naraz; spowolnienie wychodzi dopiero pod obciążeniem.

Reguły `ASYNC` w Ruff już łapią blokujące wywołania HTTP, podprocesy, `open`, `time.sleep`, `input` i `pathlib` w funkcjach asynchronicznych ([ASYNC210 do ASYNC251](https://docs.astral.sh/ruff/rules/#flake8-async-async)). Nie znają `Session` z SQLAlchemy, redis-py, boto3 ani sterowników baz danych, a typ odbiorcy zwykle wynika z adnotacji albo z klienta na poziomie modułu, nie z nazwy samego wywołania. INW013 wypełnia tę lukę, a resztę zostawia Ruffowi.

<!-- e2e -->

```python title="store/api/orders.py"
from typing import Annotated

import redis
from fastapi import APIRouter, Depends
from sqlalchemy import text
from sqlalchemy.orm import Session

from store.api.db import get_db

router = APIRouter()
cache = redis.Redis()


@router.get("/orders/{order_id}")
async def get_order(order_id: int, db: Annotated[Session, Depends(get_db)]) -> dict:
    cached = cache.get(f"order:{order_id}")
    if cached is not None:
        return {"id": order_id, "total": int(cached)}
    total = db.scalar(text("select total from orders where id = :id"), {"id": order_id})
    return {"id": order_id, "total": total}
```

Druga poprawka zostawia `async def` i przechodzi na klientów asynchronicznych: `redis.asyncio.Redis` oraz `AsyncSession` z `create_async_engine`, z każdym wywołaniem poprzedzonym `await`.

## Jak działa { #how-it-works }

Najpierw działa filtr tekstowy: plik bez `async def` albo taki, który nie wymienia żadnej z nazw `sqlalchemy`, `sqlmodel`, `redis`, `boto3`, `sqlite3`, `psycopg`, `pymysql`, `MySQLdb` i `mysql` ani pierwszego członu skonfigurowanego wzorca, nigdy nie jest parsowany. Plik, który przejdzie filtr, jest parsowany raz, na potrzeby tej reguły.

- **Funkcje:** każde `async def`, łącznie z metodami i funkcjami zagnieżdżonymi. Liczy się jego ciało aż do zagnieżdżonego `def`, `lambda` albo `class`: ich ciała nie wykonują się, gdy funkcja działa, dlatego `await anyio.to_thread.run_sync(lambda: db.execute(q))` przechodzi.
- **Nazwy** są kwalifikowane przez importy pliku, więc `from redis import Redis as Cache` i `cache: Cache` nadal znaczą `redis.Redis`.
- **Odbiorcy** pochodzą z przypisań na poziomie modułu, potem z parametrów funkcji (parametr przesłania nazwę modułu o tej samej pisowni), a na końcu z nazw przypisanych w jej ciele. Blokujące wywołanie poprzedzone `await` też jest zgłaszane: klient synchroniczny nie staje się asynchroniczny od `await`.
- **Jedno zgłoszenie na wywołanie.** `sqlite3.connect(p).execute(q)` jest zgłaszane raz, na `sqlite3.connect`; `db.query(Order).filter(...).all()` raz, na `db.query`.

## Jak naprawić { #how-to-fix }

1. Przejdź na klienta asynchronicznego tej biblioteki i dodaj `await` przed wywołaniem: `AsyncSession` i `create_async_engine` z `sqlalchemy.ext.asyncio`, `redis.asyncio.Redis`, `asyncpg` albo `psycopg.AsyncConnection`, `aiosqlite`, `aiomysql`, `aioboto3`.
2. Albo, w przypadku trasy lub zależności FastAPI czy Starlette, zadeklaruj ją jako `def`: framework uruchomi ją w puli wątków.
3. Albo zostaw wywołanie synchroniczne i uruchom je w wątku roboczym: `await anyio.to_thread.run_sync(...)`, `await asyncio.to_thread(...)` albo `run_in_threadpool`.

## Bezpieczeństwo poprawki { #fix-safety }

Bez automatycznej poprawki (`autofix: false`). Przejście na klienta asynchronicznego zmienia zależność, fabrykę sesji i każde miejsce wywołania; przejście na `def` zmienia sposób, w jaki trasa się wykonuje.

## Konfiguracja { #configuration }

Poziom error. Opt-in: włącz ją przez `extend-select`. Preset `fastapi` polecenia [`inwards init`](../guides/install.md#a-new-project-start-from-a-preset) włącza INW013 jako ostrzeżenie we wszystkich modułach. Opcje są w `[tool.inwards.rules.async-blocking]` ([tabele opcji](index.md#opt-in-rules)):

<!-- config: fragment -->

```toml title="pyproject.toml"
[tool.inwards.rules]
extend-select = ["INW013"]

[tool.inwards.rules.async-blocking]
modules = ["shop.*.router", "shop.*.service"]   # optional: only these modules
extend-blocking-calls = ["shop.legacy.fetch_*"] # calls that block by themselves
extend-blocking-types = ["pymongo.MongoClient"] # every method of these blocks
```

- `extend-blocking-calls`: kwalifikowane nazwy, z `*` i `?` jako wildcardami, funkcji, których wywołanie blokuje. Dochodzą do wbudowanych sterowników.
- `extend-blocking-types`: kwalifikowane nazwy, z `*` i `?` jako wildcardami, typów albo fabryk, których każda metoda blokuje. Parametr z taką adnotacją albo nazwa przypisana z wywołania takiego typu jest odbiorcą.

Wbudowanej listy nie da się skrócić; użyj `modules` albo wyciszenia w linii dla pojedynczego wywołania: `# inwards: ignore[INW013] reason="..."` w linii wywołania.

## Znane ograniczenia { #known-limitations }

- **Jedna funkcja naraz.** `async def`, które wywołuje funkcję `def` z własnego kodu, a ta wykonuje blokujące wywołanie, nie jest jeszcze zgłaszane ([#294](https://github.com/SirCypkowskyy/inwards/issues/294)).
- **Pośredniość.** `self.db`, klient przekazany przez `**kwargs` albo słownik, klient zbudowany przez fabrykę z innego modułu (`SessionLocal()` z `sessionmaker` w `db.py`) i alias typu zaimportowany z innego modułu albo zapisany jako napis ukrywają odbiorcę. Dodaj adnotację do parametru.
- **Ponowne przypisanie.** Nazwa zostaje odbiorcą, gdy raz stanie się nim przez przypisanie: po `db = Session(engine)`, a potem `db = AsyncSession(engine)`, `db` nadal liczy się jako blokujące.
- **Parametry bez adnotacji** nie są odbiorcami: `async def f(db)` nic nie mówi o `db`.
- **Nie każda metoda blokuje.** Rodziny `Engine`, redis-py i sterowników liczą każdą metodę poza kilkoma; rzadka metoda działająca tylko lokalnie da fałszywe zgłoszenie.
- **Kod startowy.** Asynchroniczny lifespan albo hook startowy, który raz otwiera połączenie, raz blokuje pętlę. Zawęź `modules` albo wycisz linię z powodem.
